# 照片导入工具 v5

Windows 桌面工具，从相机存储卡（含 DCIM 目录）导入 RAW/JPG 照片，按 EXIF 日期自动分类存放。
支持**多设备分流**：按机身序列号识别是哪台相机拍的，借来的卡上别人的照片不会混进你的库。

## 功能

- 自动检测含 `DCIM` 目录的存储设备（相机存储卡、读卡器、移动硬盘等）
- 按 EXIF `DateTimeOriginal` 自动分类导入（回退到文件修改时间）
- 支持 RAW（.nef/.cr2/.arw/.dng 等）和 JPG 格式
- 三种日期目录格式：`YYYY/MMDD`、`YYYY-MM-DD`、`YYYY年MM月DD日`
- 备注功能：给日期目录追加自定义标签（如"旅行"、"婚礼"）
- 排除盘符：选择不扫描特定磁盘
- 单实例保护：防止重复启动
- 导入完成后自动打开目标文件夹（可选全部/最新，RAW/JPG 多选）

## 多设备分流

### 解决的场景

借了别人的存储卡拍摄，卡上还有对方未格式化的照片。混合导入会把别人的照片
混进自己的库——**按拍摄时间或文件名都不可靠**（时间可能重叠，`DSC_0001` 这类
文件名两机完全可能撞号）。

可靠依据是 EXIF 里的**机身序列号**：每台相机唯一，且随照片一起被写入。

### 工作方式

设备管理**常驻在主界面**（没有独立弹窗，也没有单独的导入按钮），操作分三步：

1. 点「🔄 扫描卡内设备」——读取卡上每张照片的机身序列号，按序列号分组统计
2. 在「设备」下拉框里选中属于**自己**的相机，勾选「导入此设备的照片」（总开关），
   按需填写设备名；新扫描到的设备会按机型自动起个建议名
3. 点「▶ 开始导入」——程序根据设备配置自动决定走分流还是全量

```
归档根目录 (D:\D800E)/
├── _他机/          ← 未勾选设备的照片（别人的），不混进主库
│   └── 8105412/2026/0726_漫展/{raw,jpg}/
└── _未识别/        ← 读不到序列号（安全模式，不漏片）
    └── 2026/0620_导出/{raw,jpg}/

设备独立路径 (D:\D800E)/
└── 2026/0927_外景/{raw,jpg}/     ← 已勾选设备，路径即落点，不再套设备名子目录
```

设备配置以 JSON 存在注册表 `device_config` 里，下次插同一张卡无需重选。

### 界面行为

- 「设备」下拉框选中某台相机后，**二级面板**才出现（未选中时整块隐藏，
  不留空壳表单）；切换设备会重新滚到面板，切完立刻能看到改动结果
- 上半区（配置卡片）在窗口偏矮时可滚动，**按钮行与日志区固定在底部**，
  「开始导入」不会被滚动顶出视口

### 路径规则

只有一个全局路径「**归档根目录**」，它承担三件事：

| 用途 | 说明 |
|---|---|
| 全量导入 | 一台设备都没勾选时，按此目录导入 |
| 未填路径的设备 | 落到 `归档根目录\设备名` |
| 归档 | `_他机` / `_未识别` 都放在此目录下 |

每台设备可另填**独立路径**，留空则用上面的规则回退。这样一机一库（`D:\D800E`、
`D:\Z6II`）和总库下分设备两种用法都支持。

### 分流规则

| 设备状态 | 落盘位置 |
|---|---|
| 已勾选（总开关 ON） | 该设备路径（留空则 `归档根目录\设备名`） |
| 已勾选设备存在，但本台未勾选 | `归档根目录\_他机\<序列号>\` |
| 无序列号的文件 | `归档根目录\_未识别\`（安全模式） |
| 一台都没勾选 | 按归档根目录**全量导入**（与历史版本一致） |

`<日期目录>/<raw|jpg>` 这一层在所有情况下都保留。

### 设计取舍

| 决策 | 说明 |
|---|---|
| 设备管理常驻主界面 | 不做一次性弹窗：配置可见、可随时改，不用重走扫描 |
| 未勾选 → `_他机` 而非丢弃 | 规则统一（勾=我的，不勾=别人的），且不会因误操作静默丢文件 |
| 无序列号走安全模式 | 截图、导出图等没有 EXIF 的文件**默认放行**进 `_未识别`，宁可多导也不漏片 |
| 一台都没勾选则全量 | 保留旧版简单用法；「归档根目录」是唯一路径概念，避免两处路径混淆 |
| 默认设置不抹除认领 | 「默认设置」只关总开关，保留设备名与路径，免得重新认领 |

### 机型支持

- **标准 EXIF**：任何写入 `BodySerialNumber(42033)` 的机型
- **Nikon**：D800E 等机型不写标准 tag，序列号只存在 MakerNote 中，
  本工具已解析（需剥掉 10 字节 `Nikon\0\x02\x10\0` 前缀后按 TIFF 解析）
- 其他品牌若既不写标准 tag 也无对应解析器，文件会落入 `_未识别`，不影响导入

| 卡内 629 文件设备扫描（冷态，刚插卡） | 约 1 s | 约 60 s |
| 每张照片的读取次数 | **1 次** | NEF 327 次 / JPG 58 次 |
| 启动到主窗口出现 | 约 0.8 s | 1.73 s |
| 盘符探测（跳过网络盘/光驱后） | 0.00 s | 28.4 s |

> 失效的网络映射盘在目录探测时会阻塞到 SMB 超时，实测每块十余秒。
> 工具只探测可移动盘与本地盘——相机存储卡一定是这两类。

### 扫描为什么会慢（以及怎么修的）

**症状**：刚插卡点「扫描卡内设备」，要等几十秒；但同一个操作第二次跑却很快。

**根因**：机身序列号只在 Nikon MakerNote 的 tag `0x001d`，而这个 tag 位于
MakerNote IFD 的最前面几百字节。但 Pillow 读取 EXIF 时会把**整个 MakerNote
当作一块 bytes 读进来** —— 实测 Z 6_2 的 JPG 约 32KB、D800E 的 JPG 约 38KB，
NEF 则高达 **130~180KB**。再加上解析 IFD 时逐个 tag 的 seek+read，最终摊成
每张照片**数百次小块读取**：

| | read 次数 | seek 次数 | 读入字节 |
|---|---|---|---|
| NEF | 327 | 207 | 347 KB |
| JPG | 58 | 6 | 203 KB |

629 张累计约 **12 万次 read**。热缓存下这些 read 走内存，所以只要 0.9s；但
**刚插卡是冷态**，每次小块 read 都是一趟 USB 往返（实测约 0.5ms），12 万 ×
0.5ms ⇒ **约 60 秒** —— 这正是卡顿的来源，也解释了「第二次就快了」。

**对策一：一次大块读**

把文件前 `SCAN_HEAD_BYTES`（256KB）一次性读进内存，再交给 Pillow 用
`io.BytesIO` 解析。每张照片的 read 次数从数百次降到 **1 次**。

窗口大小由实测边界确定，不能用更小的值：MakerNote 是一整块、必须完整落在
缓冲里，否则 Pillow 解析不出序列号。

| 缓冲 | NEF | JPG |
|---|---|---|
| 64 KB | 0/3 | 0/3 |
| 128 KB | — | 3/3 ✓ |
| 192 KB | 2/3 | 3/3 |
| **256 KB** | **3/3 ✓** | **3/3 ✓** |

顺带把序列号、机型、拍摄时间合并成**同一次解析**取回 —— 历史实现里
`read_body_serial` 与 `get_file_date` 各开一次文件，read 次数直接翻倍
（193 + 134 = 327）。

读不到序列号且缓冲可能被截断时（将来机型 MakerNote 更大），自动回退为
Pillow 直读，保证结果不劣于历史行为。

**对策二：目录级采样**

相机写卡时按目录顺序递增，**同一个 DCIM 子目录几乎必然出自同一机身**（实测
本机卡两组分别 539 张 / 90 张，各自 100% 纯）。于是：先逐张确认前 8 张锁定
机身，之后每 12 张抽查 1 张；抽查到别的机身就**整目录回退全读**。

结果与全读**完全一致**，采样只影响耗时。629 张只需读 **68 张（省 89%）**。

另有一道**零成本预检**：相机换机身之后序号会重启（如 2000 → 0001 这种大幅
回退），只看文件名就能发现该目录混过机器，直接走全读。判定要点有两个——

- **按扩展名分开看**：RAW 与 JPG 各是一段独立序号，拼起来会在交界处产生假回退
- **只认大幅回退**（幅度 > 50）：删除照片、重拍、目录项乱序都会造成小回退，
  实测本卡出现过 `1708 → 1705`（幅度仅 3），必须容忍，否则整个目录被误推进
  全读、采样彻底失效

采样跳过的文件不再读 EXIF，日期用文件 mtime 兜底（实测 mtime 与 EXIF 拍摄
时间只差 0~12 秒，不会跨越日期边界）。

## 安装

解压 `照片快速导入工具v5/` 文件夹，双击其中的 `照片快速导入工具v5.exe`，
**无需安装 Python 环境**。分享给朋友时把整个文件夹压缩即可。

> 早期版本是单文件 exe（onefile），每次启动都要把 56MB 解压到 `%TEMP%`，
> 实测「双击到主窗口出现」需要 1.73s；改成单目录（onedir）后实测
> 0.78~1.34s，约省 0.9s。单文件版保留在 `backup/照片快速导入工具v5_扫描优化前.exe`。

