# 照片导入工具 v5

Windows 桌面工具，从相机存储卡（含 DCIM 目录）导入 RAW/JPG 照片，按 EXIF 日期自动分类存放。
支持**多设备分流**：按机身序列号识别是哪台相机拍的，借来的卡上别人的照片不会混进你的库。

## 功能

- 自动检测含 `DCIM` 目录的存储设备（相机存储卡、读卡器、移动硬盘等）
- 按 EXIF `DateTimeOriginal` 自动分类导入（回退到文件修改时间）
- 支持 RAW（.nef/.cr2/.arw/.dng 等）和 JPG 格式
- 三种日期目录格式：`YYYY/MMDD`、`YYYY-MM-DD`、`YYYY年MM月DD日`
- 备注功能：给日期目录追加自定义标签（如"旅行"、"婚礼"）
- 排除盘符：选择不扫描特定磁盘
- 单实例保护：防止重复启动
- 导入完成后自动打开目标文件夹（可选全部/最新，RAW/JPG 多选）

## 多设备分流

### 解决的场景

借了别人的存储卡拍摄，卡上还有对方未格式化的照片。混合导入会把别人的照片
混进自己的库——**按拍摄时间或文件名都不可靠**（时间可能重叠，`DSC_0001` 这类
文件名两机完全可能撞号）。

可靠依据是 EXIF 里的**机身序列号**：每台相机唯一，且随照片一起被写入。

### 工作方式

点击「🔍 多设备分流导入」后：

1. 扫描卡上全部照片，读取每张的机身序列号，按序列号分组统计
2. 弹窗列出检测到的设备（序列号 / 机型 / 张数 / 拍摄时间范围），
   你可以勾选属于**自己**的相机并填写设备名
3. 按认领结果分流落盘

```
<导入路径>/
├── D800E/          ← 已认领设备（你填的设备名）
│   └── 2026/0927_外景/{raw,jpg}/
├── Z6II/           ← 另一台已认领设备
│   └── 2026/0926_外景/{raw,jpg}/
├── _他机/          ← 未认领设备（别人的照片）
│   └── 8105412/2026/0726_漫展/{raw,jpg}/
└── _未识别/        ← 读不到序列号（安全模式，不漏片）
    └── 2026/0620_导出/{raw,jpg}/
```

认领结果会记入注册表，下次插同一张卡无需重填。

### 设计取舍

| 决策 | 说明 |
|---|---|
| 未知设备先拦截并归档 | 未认领的设备不会静默混入，而是进 `_他机/<序列号>`，日志明确列出，可事后核对 |
| 无序列号走安全模式 | 截图、导出图等没有 EXIF 的文件**默认放行**进 `_未识别`，宁可多导也不漏片 |
| 独立按钮触发 | 常规导入行为完全不变；只有点击分流按钮才启用设备识别 |
| 默认全量模式不受影响 | `device_map` 为空时退化为原有行为，目录结构与历史版本一致 |

### 机型支持

- **标准 EXIF**：任何写入 `BodySerialNumber(42033)` 的机型
- **Nikon**：D800E 等机型不写标准 tag，序列号只存在 MakerNote 中，
  本工具已解析（需剥掉 10 字节 `Nikon\0\x02\x10\0` 前缀后按 TIFF 解析）
- 其他品牌若既不写标准 tag 也无对应解析器，文件会落入 `_未识别`，不影响导入

## 性能

| 项目 | 实测 |
|---|---|
| 序列号读取 | 约 2 ms/张（1800 张全库 0.26 s） |
| 卡内 629 文件设备扫描 | 3.7 s |
| 盘符探测（跳过网络盘/光驱后） | 0.00 s（优化前 28.4 s） |

> 失效的网络映射盘在目录探测时会阻塞到 SMB 超时，实测每块十余秒。
> 工具只探测可移动盘与本地盘——相机存储卡一定是这两类。

## 安装

下载 `照片快速导入工具v5.exe`，双击运行，**无需安装 Python 环境**。

## 从源码构建

```bash
pip install pyqt5 pillow pyinstaller
pyinstaller --clean --noconfirm build.spec --distpath dist --workpath build
```

### 验证

```bash
python verify_split.py
```

26 项断言：序列号读取（含 Nikon MakerNote）、设备名清理防路径注入、
白名单序列化往返、端到端分流拷贝、向后兼容全量模式。
